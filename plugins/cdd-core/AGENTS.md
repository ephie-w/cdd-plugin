# CDD discovery

For every development request that would change code, run `/cdd-core:discover` before editing code. Record the matched CDD capability and why it fits, or explicitly report `no match` with a reason. Do not force CDD adoption when no capability fits. A non-code question does not require this pre-edit check.

Start from the bundled catalogue, then read relevant authoritative sources before making source-specific claims. A `draft` pattern or `candidate` component is not approved. A plugin declared by the marketplace is not necessarily active in the current session. When a component plugin is missing, give the discover skill's installation handoff and mark its skill as not run; do not substitute a manual reading of that skill's repository copy.
